# Тестовый сервер ss12.org

*[English version](README.md)*

В этой папке то, на чём работает публичный тестовый сервер SS12 (`lol.ss12.org`): копия Wizard's Den с установленным SS12
и несколько изменений, которые имеют смысл только для этого сервера. **Это не часть установщика SS12.** Серверы,
которые ставят SS12, этих файлов не получают; они лежат здесь, чтобы тестовый сервер можно было пересобрать из этого
репозитория.

## Что здесь есть

| Путь | Что это |
|------|---------|
| `ss12.org.patch` | Изменения в существующих файлах, сделанные для коммита Wizard's Den `fb9401cf` (движок 291). |
| `files/` | Новые бинарные файлы, которые патч не может нести (фон лобби). |
| `apply.sh` | Применяет патч и файлы к копии кода, в которую уже установлен SS12. |
| `deploy/` | Настройки сервера, unit-файлы systemd и скрипт, которые используются на хосте. |
| `tools/make_lobby_bg.py` | Рисует фон лобби кодом (без чужих рисунков). |
| `deploy/analytics/` | Простая закрытая статистика сайта и сервера (см. «Простая статистика» ниже). |

## Что делают изменения

- **Приветственные страницы.** Окно, которое появляется при первом входе, и окно «Правила и информация» показывают
  страницу SS12 вместо правил Wizard's Den: сначала управление (с теми клавишами, которые назначены у игрока), потом что
  это за сервер, ссылки и благодарности. Первая страница Руководства (она открывается сама у новых игроков) и вступление
  на вкладке «Обучение» переписаны так же, а приветствия в чате говорят про SS12.
- **Внешние ссылки.** Ссылки, начинающиеся с `https://`, в окне правил и в Руководстве открываются в браузере (раньше
  они вели только на статьи Руководства).
- **Фон лобби.** Один фон, нарисованный `tools/make_lobby_bg.py`: заголовок, таблица управления (ходьба, обзор, вид от
  первого / третьего лица, удержание Alt освобождает мышь, миникарта, настройки 3D, 3D / плоский вид), три коротких совета и
  три персонажа внизу. Сцена помещена в левые 72% картинки, потому что лобби рисует панель чата поверх правой части, немного
  обрезает верх и низ и размещает свои кнопки в левом верхнем углу, а титры в левом нижнем. Если клавиша меняется, измените
  таблицу в скрипте и нарисуйте картинку заново.

## Как пользоваться

```bash
ss12 install path/to/space-station-14        # сначала SS12
servers/ss12.org/apply.sh path/to/space-station-14
ss12 package path/to/space-station-14
```

Затем возьмите `deploy/server_config.toml` как настройки сервера. Это базовая конфигурация Wizard's Den без частей,
которые относятся только к официальным серверам (контакт IPIntel, паник-бункер, их политика конфиденциальности), плюс
настройки SS12. Проверьте файл перед тем, как использовать его у себя: имя хоста, адрес и `hub.advertise` относятся к
этому серверу.

## Перезапуски, которые никого не выкидывают

`deploy/ss14-restart-if-empty.sh` запускается каждые 10 минут таймером `ss14-restart.timer`. Пока подключён хоть один
игрок, он ничего не делает (число игроков, которое сообщает сервер, считает и админов, для этого задано
`admin.admins_count_in_playercount = true`). Когда сервер пуст, он ставит новую сборку, если она лежит в
`/opt/ss14/pending/server.zip` (старая сборка сохраняется в `/opt/ss14/server_prev`), и новую конфигурацию, если она лежит
в `/opt/ss14/pending/server_config.toml` (сначала проверяется, что это корректный TOML; старая сохраняется как
`server_config.toml.prev`). Если ничего не подготовлено, сервер перезапускается ради нового раунда, когда проработал не
меньше трёх часов (после каждого перезапуска первому вошедшему игроку приходится ждать, пока игра компилирует свой код). Подготовка файла никак не мешает работающему серверу. Если страница состояния сервера перестала отвечать (так бывает,
когда много загрузок клиентов брошено на середине), скрипт считает игроков по журналу сервера и перезапускает зависший
сервер, как только их число станет нулём. Сервер, который запущен меньше трёх минут назад, скрипт не трогает: страница состояния у него ещё не открылась.

## Облегчённая настройка

Тестовый сервер работает на небольшой машине, поэтому он настроен так, чтобы на каждый тик уходило меньше:
`Resources/Prototypes/Maps/Pools/default.yml` (входит в `ss12.org.patch`) оставляет только четыре карты с наименьшим числом
сущностей (Elkridge, Packed, Exo, Snowball), `Resources/Prototypes/Entities/Stations/base.yml` создаёт вокруг станции 2 космических
крушения и 1 руины вместо 12–16 и 2 и не создаёт добывающий астероид (один астероид давал около 50 000 из 81 000 сущностей
раунда и большую часть 16–25 секунд работы сервера на создание дополнительных сеток раунда), `nanotrasen.yml` убирает из
станции соляжный магнит, экспедиции и доску заданий, а на четырёх картах пула нет мест для Salvage Specialist, поэтому
добычи нет вообще, `deploy/server_config.toml` отключает ИИ существ (`npc.enabled = false`), а
скрипт перезапуска ждёт, пока сервер проработает три часа, прежде чем перезапустить пустой сервер ради нового раунда.

## Простая статистика

`deploy/analytics/` считает визиты на сайт и игроков на сервере без сторонних сервисов, cookies и лишних служб.

- **Сайт.** Веб-сервер (Caddy) пишет журнал запросов, из которого убраны cookies и учётные данные, а адрес посетителя
  обрезан до сети (`/24` для IPv4, `/48` для IPv6). `script.js` страницы отправляет крошечный запрос на `/a/<имя>`, когда
  посетитель копирует адрес сервера, открывает скриншот или переходит по ссылкам на GitHub и Space Station 14; строка в
  журнале и есть подсчёт. Браузеры, которые присылают Do Not Track или Global Privacy Control, не попадают ни в один подсчёт.
- **Сервер.** `ss12-stats sample` (каждую минуту запускается `ss12-stats-sample.timer`) записывает число игроков с
  адреса состояния сервера. `ss12-stats report` добавляет из базы данных игры (она открывается только на чтение): игроков
  по дням, новых игроков, входы, раунды и среднее время игры, не учитывая имена из `exclude_names`.
- **Что сохраняется.** В журнале сайта есть время, страница, строка с названием браузера, сайт-источник и адрес посетителя,
  обрезанный до сети (например, `203.0.113.0`); страну не определяют и cookies нет. Для данных сервера берутся только
  идентификатор и имя учётной записи и время из базы данных игры, а отчёт выводит числа, но не имена и не адреса. (Сама
  игра, как любой сервер SS14, хранит полные адреса в своей базе и журнале; статистика их не читает и не показывает.)
- **Как смотреть.** `ss12-stats report [--days N]` выводит сводку. `ss12-stats-report.timer` ещё раз в час пишет страницу,
  которую Caddy отдаёт по адресу `/stats/` под паролем (в `Caddyfile.example` показано как; хеш делается командой
  `caddy hash-password`).
- **Установка.** Запустите `deploy/analytics/install.sh` от root на сервере, добавьте `Caddyfile.example` в
  `/etc/caddy/Caddyfile` (подставьте `STATS_PASSWORD_HASH`) и скопируйте `script.js` страницы. `ss12-stats selftest`
  проверяет скрипт на выдуманных данных.

На странице есть короткая заметка о приватности (внизу), как устроен подсчёт; держите её в соответствии с этими настройками.

## Заметки

- Патч привязан к одному коммиту Wizard's Den. Для другой версии пересоздайте его: внесите изменения вручную в копию
  этой версии и выполните `git diff` для файлов из патча.
- `tools/make_lobby_bg.py <копия SS14> <файл.png>` требует Pillow (`pip install pillow`) и берёт шрифт Boxfont Round из
  этой копии.
