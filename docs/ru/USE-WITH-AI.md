# Пусть всё сделает ИИ-ассистент

*[English version](../USE-WITH-AI.md)*

На большинство серверов 3D ставится в один клик (см. [INSTALL-ON-YOUR-SERVER.md](INSTALL-ON-YOUR-SERVER.md)). Но если
исходный код вашего сервера сильно изменён, установщик может остановиться и сообщить *"I could not find the place to
change"* (не удалось найти место для правки). Вот тут и пригодится ИИ-ассистент. Установщик умеет напрямую общаться с
ИИ-ассистентами, так что ассистент может прочитать ваш код, разобраться, как вписать 3D с учётом ваших изменений, и
внести правки за вас.

Программировать уметь не нужно. Нужен ИИ-ассистент, который поддерживает **MCP-серверы** (стандартный способ дать
ассистенту дополнительные инструменты). Примеры: Claude Desktop, Claude Code, Cursor, VS Code с ИИ-расширением.

> **Вы остаётесь главным.** Пока вы не скажете «да», ассистент может только смотреть. Установка, обновление и удаление
> 3D всегда начинаются с *предварительного просмотра* («пробный запуск»), который ничего не меняет. Установщик никогда
> ничего никуда не загружает и не отправляет.

## Шаг 1: подключите ассистента к установщику

**Проще всего (Windows, Mac, Linux):** запустите скрипт установщика (`Install 3D.bat` или `install-ss12.sh`), выберите
папку своего сервера и выберите пункт **6 Use an AI helper** (использовать ИИ-помощника). Он создаст небольшой файл
`ss12-ai-config.json` с правильными настройками, в которых уже указан нужный путь.

Откройте этот файл, скопируйте всё его содержимое и вставьте в настройки MCP вашего ассистента:

| Ассистент | Куда вставить |
|-----------|---------------|
| Claude Desktop | Settings, Developer, Edit Config. Вставьте в `claude_desktop_config.json`, затем перезапустите приложение. |
| Cursor | Settings, MCP, Add new MCP server (или отредактируйте `.cursor/mcp.json`). |
| VS Code | Создайте `.vscode/mcp.json` в папке вашего сервера (VS Code называет верхний ключ `servers` вместо `mcpServers`). |
| Claude Code | В терминале: `claude mcp add ss12 -- "C:/path/to/ss12.exe" mcp` |

Если хотите написать его сами, он выглядит так (укажите настоящий путь к `ss12.exe`, со слешами `/`):

```json
{
  "mcpServers": {
    "ss12": {
      "command": "C:/Tools/ss12/ss12.exe",
      "args": ["mcp"]
    }
  }
}
```

## Шаг 2: попросите

Откройте своего ассистента и скажите что-нибудь вроде:

> Add 3D to my Space Station 14 server code at `C:\MyServer\space-station-14`.

(Перевод: «Добавь 3D в исходный код моего сервера Space Station 14 в `C:\MyServer\space-station-14`». Ассистенту можно
написать и по-русски, и свой путь подставьте вместо примера.)

(Также есть готовый запрос под названием **add_3d_to_my_server** в ассистентах, которые показывают MCP-запросы.)

Что происходит дальше, простыми словами:

1. Ассистент **осматривает** ваш код: достаточно ли новый движок игры, в порядке ли ваша папка git, какие из небольших
   правок подходят автоматически, а какие нет.
2. Он **показывает вам предварительный просмотр** того, что изменится, и спрашивает, всё ли в порядке.
3. Для всего, что автоматически не подходит (потому что в этом месте ваш сервер изменён), он читает точное описание
   того, чего должна достичь эта правка, находит подходящее место в вашем коде и вручную вносит равноценное
   изменение. Он расскажет вам, что сделал.
4. Он **устанавливает** остальное, затем **проверяет**, что ваш сервер по-прежнему собирается, и исправляет ошибки
   сборки, которые может.
5. Он простыми словами говорит вам, что делать дальше.

## Что ассистент может делать (и чего не может)

| Инструмент, который получает ассистент | Что он делает | Меняет файлы? |
|----------------------------------------|---------------|---------------|
| `inspect_codebase` | Осматривает ваш код и сообщает, что подходит, а что нет | Нет |
| `list_edits` / `explain_edit` | Описывает каждую небольшую правку существующих файлов и зачем она нужна | Нет |
| `find_edit_location` | Ищет в вашем коде место, куда относится правка | Нет |
| `check_install` | Проверяет, что установка 3D полная (по желанию компилирует) | Нет |
| `build_codebase` | Компилирует ваш клиент и сервер и объясняет ошибки | Только результаты сборки |
| `install_3d` / `update_3d` / `uninstall_3d` | Устанавливает, обновляет или удаляет 3D | Только при `dry_run=false`; по умолчанию это предварительный просмотр |

Папку движка игры (`RobustToolbox`) он трогать не может, а установщик никогда ничего не отправляет на удалённые
репозитории и не обращается к ним. Всё попадает в одну ветку git (она называется `ss12`) и один коммит, так что вы можете
просмотреть результат или выбросить ветку.

## Советы

- **Сначала сделайте коммит или stash своей работы.** Установщику нужна аккуратная папка git, чтобы результат было легко
  просмотреть.
- **Прочитайте предварительный просмотр**, прежде чем сказать «да». В нём перечислен каждый файл.
- **Что-то странное после установки?** Выберите в скрипте установщика *Remove 3D* (удалить 3D): ваши файлы вернутся
  ровно такими, какими были.
- **Всё равно не получается?** Запустите `Install 3D`, выберите *Check an install* (проверить установку) и приложите
  `ss12-report.txt`, когда будете просить помощи на странице обращений (issues) проекта.

## Для любопытных

`ss12 mcp` говорит по протоколу Model Context Protocol через стандартный ввод и вывод (JSON-RPC 2.0), не использует
сеть и предоставляет перечисленные выше инструменты, а также два документа (`ss12://guide`, `ss12://edits`) и один
запрос. Всё, что записывается в его вывод, относится только к протоколу; читаемый человеком вывод возвращается как
результаты инструментов.
