# Для разработчиков

Эта страница для тех, кто хочет читать или менять код. Всем остальным: см. [README](../../README.ru.md).

## Идея в одном абзаце

SS12 — это *только контент*: в игровом движке (RobustToolbox) ничего не меняется. Обычный 2D-рендерер запускается во
внеэкранный вьюпорт вокруг камеры. Мировой оверлей копирует освещённый слой пола в текстуру. Затем фрагментный шейдер
выполняет рэймарчинг (raymarch) карты тайлов (стены) на GPU и накладывает текстуры на полы, потолки и космос. Каждая видимая сущность отрисовывается через
`DrawEntity` в покадровый атлас, а затем как 3D-квад с проверкой глубины (биллборды, плоские предметы, створки дверей, окна,
столы, декали на стенах). Ввод идёт через `IViewportControl`, поэтому все существующие 2D-системы, преобразующие экранную позицию
в мировую, продолжают работать с прицелом. Цепочка постобработки (свечение, затенение углов, grade, виньетка) необязательна, и у каждого эффекта
есть свой переключатель.

## Что находится в этом репозитории

| Папка | Что |
|-------|-----|
| `overlay/` | Каждый файл, который установщик **добавляет** в исходный код сервера: `Content.Client/Render3D`, `Content.Shared/Render3D`, `Content.Server/Render3D`, шейдеры, прототипы, локализация, тесты, заметки. Это сгенерированная копия рабочего кода (см. ниже), расположенная так же, как собственные папки сервера. |
| `installer/` | Установщик — одна небольшая программа на .NET без пакетов (`ss12`). Команды: `install`, `update`, `uninstall`, `doctor`, `package`, `selftest`, `mcp`. |
| `scripts/` | Обёртки для запуска двойным щелчком для нетехнических пользователей, `demo/` (запуск демо на Windows и Linux), `server/` (пакет Linux-сервера: `run-server.sh`, пример конфигурации, юнит systemd) и `ci/` (вспомогательные скрипты для рабочих процессов). |
| `docs/` | Руководства. |
| `.github/` | Формы для issue, CI (`selftest` установщика), релизная сборка и сборка демо и Linux-сервера. |

Установщик **правит** несколько существующих файлов в исходном коде сервера (прицеливание, выбор объектов, всплывающие сообщения, map text, растворение
спрайтов, полосы здоровья). Каждая правка описывается тем, как выглядит код (регулярное выражение), а не номерами строк, является
идемпотентной, и её причина и влияние указаны в `installer/BuiltIn.cs`. `ss12 mcp` и
[USE-WITH-AI.md](USE-WITH-AI.md) предоставляют те же описания ИИ-ассистенту.

## Сборка и тестирование установщика

Нужен .NET 10 SDK.

```bash
dotnet build installer/ss12.csproj -c Release
dotnet installer/bin/Release/net10.0/ss12.dll selftest
```

`selftest` создаёт одноразовые тестовые кодовые базы (с окончаниями строк LF и CRLF), а затем проверяет: установку, отказ при повторной установке,
обновление, doctor, удаление, возвращающее побайтово идентичные файлы, остановку без записи чего-либо при отсутствии обязательной правки, лишь
ухудшение работы при отсутствии необязательной правки, более новый вариант оверлея полос здоровья, папку, не являющуюся SS14, и
MCP-сервер по его протоколу. Движок и сеть ему не нужны. Релизная сборка тоже его запускает.

## Где разрабатывается 3D-код

Набор файлов 3D (overlay) генерируется из дерева разработки: кодовой базы Space Station 14 с установленным 3D-видом в отдельной ветке.
Это дерево не входит в данный репозиторий. Если вы хотите изменить сам 3D-код, проще всего так:

1. Возьмите любую кодовую базу SS14 на движке 286 или новее и установите в неё 3D установщиком.
2. Правьте файлы в `Content.Client/Render3D`, `Content.Shared/Render3D`, `Content.Server/Render3D` и `Resources/...`.
3. Соберите и запустите (`dotnet build`, затем запустите `Content.Server` и `Content.Client`).
4. Скопируйте изменённые файлы обратно в `overlay/` здесь (с теми же относительными путями). В `installer/overlay.manifest` перечислено, какие
   пути относятся к набору файлов 3D.

Для 3D-кода помощники разработчика находятся в `overlay/Tools/render3d-dev/`, а справочник настроек и
список консольных команд — в `overlay/docs/ss12/README.md`. Запустите клиент с `--cvar render3d.dev_channel=true
--cvar player.name=<name>`, и файл `render3d_dev_<name>.txt` в пользовательской папке данных клиента станет каналом команд
(`r3d_shot`, `r3d_look`, `r3d_press`, `render3d_fx`, ...). Удобно для скриншотов и скриптовых тестов.

## Правила, которым следует 3D-код (пожалуйста, соблюдайте их)

- **Только контент.** Ничего в `RobustToolbox/`. Игроки используют официальный лаунчер и получают 3D-клиент с
  сервера, как любой другой контент.
- **Никаких новых пакетов NuGet в `Content.*`.**
- **Оставайтесь внутри клиентской песочницы.** Например, никакого `[ThreadStatic]`, никакого `StackTrace`. Нарушения проявляются только при
  запуске клиента, поэтому после любого изменения всегда запускайте его.
- **У каждого визуального эффекта есть свой переключатель** и место в пресетах Low / Medium / High, чтобы на старых компьютерах
  его можно было отключить.
- **У шейдеров (swsl) есть особенности:** нет `return` в `fragment()`, нет литералов с экспонентой (`1e-5`), `fwidth` должен быть встроен прямо
  в `fragment()`, вспомогательные функции компилируются и в вершинную стадию, а параметры экземпляра шейдера считываются в момент
  отрисовки, поэтому дайте каждому направлению размытия собственный экземпляр.
- **Правки существующих файлов сервера остаются крошечными** (один вызов нового кода) и пишутся с полными квалифицированными
  именами, чтобы строки `using` не менялись.

## Тесты самого 3D-кода

Они находятся в наборе файлов 3D (`Content.Tests/**/Render3D`, `Content.IntegrationTests/Tests/Render3D`) и копируются вместе с ним в исходный
код сервера, так что собственный запуск тестов сервера их охватывает: `dotnet test Content.Tests` и интеграционные тесты,
отфильтрованные по `Render3D`.

## Выпуск релиза

Отправьте тег версии (например, `v1.0.1`). `.github/workflows/release.yml` собирает установщик для Windows, Linux и
macOS, объединяет его с `overlay/`, руководствами и скриптами для запуска двойным щелчком, запускает `selftest` на результате и прикладывает
zip-архивы к релизу на GitHub. Сначала обновите `installer/version.txt` и `CHANGELOG.md`.

Тот же тег запускает и `.github/workflows/demo.yml`: он собирает `SS12-demo-windows.zip`, `SS12-demo-linux.zip` и
`SS12-server-linux-x64.zip` из коммита оригинального репозитория и прикладывает их к релизу. Linux-задачи запускают
распакованный сервер и ждут, пока он начнёт принимать подключения; видеокарты на раннерах нет, поэтому окно Linux-клиента
там не проверяется.
