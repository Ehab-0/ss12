# SS12

*[English version](README.md)*

**SS12 — это SS13 в 3D на базе SS14.** (Технически это игра SS14, увиденная в 3D; название — это подача.)

Только 3D-вид Space Station 14 с камерами от третьего лица (по умолчанию) и от первого лица. Геймплей, правила, роли,
баланс и поведение мультиплеера — как в оригинальном проекте (upstream). Всё реализовано в коде контента
(`Content.Client`, немного в `Content.Shared`/`Content.Server`); **`RobustToolbox/` не затронут**, поэтому игроки
заходят через официальный лаунчер.

## Быстрый старт

Нужны .NET SDK версии, закреплённой в `global.json` (10.0.100), и видеокарта с OpenGL 3.3.

```
dotnet build --configuration DebugOpt -m
# server: 3D enforced, straight into a round
cd bin/Content.Server && ./Content.Server.exe --cvar render3d.enforced=true --cvar physics.relative_movement=true --cvar shuttle.camera_rotation_locked=true --cvar game.lobbyenabled=false
# client (run twice with different --username values for a two player test)
cd bin/Content.Client && ./Content.Client.exe --connect --connect-address 127.0.0.1 --username player1
```

После сборки `Release` выполните `dotnet restore`, прежде чем снова собирать `DebugOpt` (обе конфигурации используют общий `obj/`).

## Управление

| Действие | Клавиша по умолчанию (переназначается в Options > Controls > 3D view) |
|----------|-----|
| Обзор | мышь (захвачена, пока окно игры в фокусе и не открыто ни одно окно или меню) |
| Движение | WASD относительно направления взгляда камеры |
| Использовать / атаковать / стрелять / бросать | щелчок левой кнопкой по прицелу (те же привязки, что и в 2D) |
| Переключить 3D / 2D (если разрешено) | `F12` |
| Переключить вид от первого / третьего лица | `N` |
| Освободить мышь (удерживать) | `Alt` (щелчок с Alt сохраняет обычное значение) |
| Окно настроек 3D (общие, клавиши, обзор, графика, форма предметов) | `F11` или консольная команда `render3d_settings` |
| Расстояние камеры от третьего лица | существующие клавиши приближения / отдаления (0.8 - 3.0) |

Всё, что открывает окно, меню или всплывающее окно, а также активное поле чата, автоматически освобождает мышь и
возвращает её обратно, когда вы закончили. Когда мышь свободна, щелчок по миру пускает луч через курсор, а не через прицел.
Пока мышь захвачена, прицел служит «мышью» для всех систем: оружие, ближний бой, взаимодействие, бросок, перетаскивание,
контекстное меню, осмотр и подсветка целей — всё это нацелено на него (`Render3DPointer`).

Прицел становится зелёным, а подпись с названием остаётся белой, когда предмет под ним находится в пределах досягаемости руки (1.5 тайла, либо он в руках или надет); вне досягаемости прицел остаётся белым, а подпись серой. Это помогает отличить «слишком далеко, чтобы подобрать / открыть / надеть наручники» от «не та цель».

Options > 3D: поле зрения, чувствительность мыши, масштаб рендера, инверсия оси Y, названия у прицела, старт от первого лица и
переключатель включения 3D-вида.

## Размещение 3D-сервера

Примените пресет `Resources/ConfigPresets/Build/render3d.toml` (или задайте cvar вручную):

| CVar | Значение | Зачем |
|------|----------|-------|
| `render3d.enforced` | `true` | Живые игроки не могут вернуться к 2D (призраки, активные администраторы и лобби могут). |
| `physics.relative_movement` | `true` | WASD движется относительно рыскания (yaw) камеры. |
| `shuttle.camera_rotation_locked` | `true` | Клавиши поворота камеры на 90 градусов в 3D бессмысленны. |

Игрокам не нужно ничего особенного: подойдёт стандартный лаунчер. Сервер, не задающий `render3d.enforced`, позволяет каждому
игроку выбирать 2D или 3D клавишей `Toggle3DView`.

## Справочник настроек

Всё действует на стороне клиента, если не указано иное. Значения по умолчанию — в скобках; большинство также есть в Options > 3D.

| CVar | Значение |
|------|----------|
| `render3d.enabled` (true) | Использовать 3D-вид вообще. |
| `render3d.enforced` (false, сервер, реплицируется) | Живым игрокам нельзя использовать 2D. |
| `render3d.yaw_send_rate` (12, клиент) | Сколько обновлений направления камеры в секунду клиент отправляет, пока мышь поворачивает обзор (от 4 до 30). Меньше значение — меньше трафика при потерях пакетов; WASD следует за новым направлением с этой частотой. |
| `render3d.settings_on_join` (0, сервер, реплицируется), `render3d.settings_shown` (false) | Сам открывает окно настроек 3D, когда игрок входит в раунд: 0 никогда, 1 только в первый раз (`settings_shown` запоминает это на компьютере), 2 в каждом раунде. |
| `render3d.wall_height` (2.3), `eye_height` (0.9) | Ширина тайла — 1 единица; значения 1.25 / 0.75 из плана оказались тесными, поэтому помещения высотой 2.3 тайла (есть и ползунок в окне F11). |
| `render3d.table_height` (0.45), `effect_height` (0.6), `ui_anchor_height` (0.9) | Где находятся столешницы, плоские эффекты и плавающие подписи. |
| `render3d.fov` (80, градусы, целое число) | Вертикальное поле зрения. |
| `render3d.render_scale` (1.0) | Разрешение 3D-сцены относительно окна (меньше 1 — рисуется меньше пикселей). |
| `render3d.supersample` (2.0) | Сглаживание суперсэмплингом: сцена рисуется в указанное число раз крупнее окна по каждой оси и усредняется вниз, что убирает мерцание и «лесенку» на всех поверхностях. 1 = выключено. Ограничивается автоматически, чтобы сцена не превышала примерно 4K пикселей. Пресеты Low / Medium / High задают 1.0 / 1.5 / 2.0. |
| `render3d.ground_radius` (24) | Количество тайлов вокруг камеры, захватываемых из 2D-рендерера. |
| `render3d.atlas_size` (2048), `billboard_cap` (400) | Размер атласа спрайтов и максимальное число отрисовываемых сущностей (сначала ближайшие). |
| `render3d.tp_distance` (1.6) | Расстояние камеры от третьего лица (также меняется клавишами приближения). |
| `render3d.mouse_sensitivity` (1.0), `invert_y` (false) | Обзор мышью. |
| `render3d.crosshair_names` (true) | Название того, что находится под прицелом. |
| `render3d.first_person` (false) | Начинать от первого лица. |
| `render3d.quality` (2), `render3d.auto_quality` (true), `render3d.auto_quality_fps` (45) | Пресет (0 низкий, 1 средний, 2 высокий, 3 пользовательский) и автоматическое понижение. |
| `render3d.fx.bloom`, `fxaa`, `ao`, `surface`, `ambient`, `shadows`, `outline`, `sharp`, `grade`, `haze`, `sky`, `fixtures`, `glass`, `head_bob`, `item_lift`, `item_lean`, `item_thick`, `char_lean`, `char_thick`, `object_lean`, `object_thick` | Отдельные эффекты (см. выше). |

## Графика и отключение эффектов для старых ПК

Каждый визуальный эффект включается и выключается отдельной настройкой, поэтому на старых машинах можно отключить ровно то, что
им не по силам. Откройте окно настроек (`F11`) и используйте раздел **Graphics**: пресет качества (Low / Medium / High) и по одному
флажку на каждый эффект. Если переключить один эффект вручную, пресет будет показан как «Custom». Те же переключатели есть и в виде консольных команд:
`render3d_quality low|medium|high` и `render3d_fx <effect> on|off` (`render3d_fx` без аргументов выводит их список).

| Эффект (имя в `render3d_fx`) | Что делает | Low | Medium | High |
|------------------------------|------------|:---:|:------:|:----:|
| `bloom` | свечение (bloom) вокруг ламп и экранов | - | - | on |
| `fxaa` | сглаживает силуэты стен и полов (с учётом глубины, пиксели спрайтов остаются чёткими) | - | on | on |
| `ao` | мягкие тени в углах и под предметами (затенение углов, screen-space ambient occlusion) | - | - | on |
| `surface` | затенение стен/полов/потолков: затемнение краёв, блик на полу, потолочные панели | - | on | on |
| `ambient` | слабый свет на стенах, полах и потолках, которые 2D-линия видимости оставляет неосвещёнными, чтобы камера от третьего лица не показывала чисто чёрные дыры (сущности там остаются скрытыми) | - | on | on |
| `shadows` | контактные тени под персонажами, предметами и брошенными вещами | - | on | on |
| `outline` | тонкий тёмный контур у персонажей и предметов | - | - | on |
| `sharp` | sharp-bilinear спрайты: без мерцания и «лесенки», пиксели остаются чёткими | - | on | on |
| `grade` | тональная компрессия, цветокоррекция, виньетка, дизеринг | - | on | on |
| `haze` | дымка вдаль, окрашенная местным светом | - | - | on |
| `sky` | многослойные звёзды и слабая туманность | - | on | on |
| `fixtures` | настенные лампы получают мягкое свечение (у потолка они висят на любом уровне) | - | on | on |
| `glass` | окна, окна-двери и решётки рисуются как прозрачное стекло (тонкая рама и почти прозрачное стекло) вместо вида сверху из спрайта, который выглядел как глухая стена | on | on | on |
| `head_bob` | лёгкое покачивание при ходьбе от первого лица | - | - | - |
| `item_lift` | предметы на полу слегка приподняты и получают контактную тень и тонкий контур, поэтому выглядят предметами, а не пятнами | - | on | on |
| `item_lean` | предметы на полу наклоняются к камере (до 20 градусов, при взгляде строго вниз — нет) | - | on | on |
| `item_thick` | предметы на полу получают толщину | - | on | on |
| `char_lean` | персонажи (и тела на полу) слегка откидываются назад / наклоняются | - | on | on |
| `char_thick` | персонажи получают толщину | - | - | on |
| `object_lean` | автоматы, мебель и другие стоящие объекты слегка откидываются назад | - | - | on |
| `object_thick` | автоматы, мебель и другие стоящие объекты получают толщину | - | - | on |

Low — это простой вид (и в нём рисуется меньше объектов: предел сущностей 200, дальность обзора 16 тайлов). **Автоматическое качество** включено по
умолчанию: если средняя частота кадров остаётся ниже 45 FPS около пяти секунд после 10-секундного прогрева, игра понижает
пресет на один уровень и сообщает об этом игроку (`render3d.auto_quality`, `render3d.auto_quality_fps`); если всё
уже выключено, в крайнем случае снижается масштаб рендера. Оно никогда не повышает пресет и не трогает пользовательскую (Custom) конфигурацию. На
Radeon RX 580 при 1600x900 весь пресет High стоит около 0.65 мс на кадр (342 FPS на Low, 280 FPS на High при 20 дополнительных
персонажах в поле зрения).

## Форма предметов: наклон и толщина

Спрайты — плоские картинки, поэтому по умолчанию предмет на полу выглядит наклейкой, и его легко принять за пятно
(лужи и декали входят в изображение пола). Эффекты «формы» придают вещам объём; каждая категория включается отдельно
(окно настроек, раздел **Shape of things**, или `render3d_fx <эффект> on|off`):

| Категория | Переключатели | Что происходит |
|-----------|---------------|----------------|
| Предметы на полу (и брошенные) | `item_lift`, `item_lean`, `item_thick` | слегка приподняты, с контактной тенью и тонким контуром; наклонены к камере до 20 градусов (меньше, чем сильнее камера смотрит вниз); рисуются как небольшая плитка с толщиной |
| Персонажи (в том числе лежащие тела) | `char_lean`, `char_thick` | откинуты назад до примерно 17 градусов, чтобы выглядеть менее приплюснутыми сверху; тонкая плитка |
| Объекты (автоматы, мебель, прочие стоящие вещи) | `object_lean`, `object_thick` | то же, что у персонажей |

Толщина рисуется *стопкой спрайтов*: копии спрайта кладутся позади лицевой стороны вдоль её нормали, темнея с глубиной,
так что бока силуэта видны, как бока плитки (`render3d.thickness_layers` слоёв, вдвое меньше дальше 9 тайлов, нет
дальше 17 тайлов, и не больше 3000 дополнительных квадов за кадр). Кликабельна и обводится только лицевая сторона.
Наклон — это простой поворот квада спрайта вокруг ближнего края (плоские вещи) или основания (стоящие вещи); выбор
объекта мышью использует наклонённый квад, так что по нему проще попасть.

Список `glass` в прототипе `render3dRules` говорит, как рисуются окна, окна-двери и решётки при включённом эффекте `glass`:
`tint` и `alpha` стекла (0 прозрачно, 1 непрозрачно), цвет рамы `frame` и `frameWidth` (в пикселях картинки тайла 32 на 32),
необязательная мелкая сетка `mesh` (шаг в пикселях, для решёток) с цветом `meshColor` (может содержать альфу, `#rrggbbaa`)
и `shine` для слабого диагонального блика. Картинка строится по этим данным и записывается в атлас спрайтов вместо спрайта;
слои спрайта выше первого (трещины повреждённого окна) по-прежнему рисуются поверх. Побеждает ближайший предок,
а `disabled: true` оставляет спрайт (угловые и диагональные окна). Открытая окно-дверь тоже остаётся спрайтом. Прототипы,
которых нет в списке, рисуются по спрайту, как раньше.

Для отдельных прототипов список `shapes` в прототипе `render3dRules` (`Resources/Prototypes/Render3D/rules.yml`)
переопределяет толщину (в тайлах, 0 = тоньше бумаги) и может запретить наклон (`lean: false`). Он сопоставляется с id
прототипов и их потомков (побеждает ближайший предок) и с именами компонентов, как и список `rules`; неизвестные имена
игнорируются. У сущности также может быть компонент `Render3D` с полями `thickness` / `lean`. По умолчанию: 0.06 тайла
для предметов, 0.16 для персонажей и 0.14 для прочих объектов; поставляемые правила делают бумагу, ID-карты и гильзы
почти плоскими, а ящики с инструментами — толще.

## Более слабые машины

`render3d.render_scale 0.5`, `render3d.billboard_cap 200`, `render3d.ground_radius 16`. По умолчанию игра уже работает примерно
на 200 FPS без ограничения на Radeon RX 580 при 1080p, так что это нужно только для заметно более слабых видеокарт.

## Устранение неполадок

- **Изображение чёрное или игра падает при запуске:** нужен OpenGL 3.3. Попробуйте `--cvar render3d.enabled=false`, чтобы убедиться,
  что 2D-игра по-прежнему работает, затем обновите драйвер видеокарты.
- **FPS застрял около 60 или ниже, когда окно перекрыто:** это вертикальная синхронизация ОС, ограничивающая перекрытое окно (так же
  и в 2D). Отключите вертикальную синхронизацию в Options > Graphics, чтобы измерить.
- **Мышь остаётся свободной / обзор не работает:** окно должно быть в фокусе, и не должно быть открыто ни одного окна, всплывающего окна или активного
  текстового поля. Удерживайте или нажмите `Alt`, чтобы проверить, не в свободной ли мыши причина.
- **Элемент интерфейса по-прежнему выглядит как в 2D (контуры и т. п.):** см. [Известные ограничения](#известные-ограничения).
- **Всё слишком тёмное или слишком яркое:** используется собственное освещение игры; проверьте 2D-вид клавишей `F12` (если разрешено).
- **Окно Options падает при открытии из отладочной консоли:** уже существующая в DebugOpt проверка (assertion) движка, которая срабатывает и
  без этого изменения; из меню окно открывается нормально.

## Известные ограничения

- Диагональные стены (и диагональные окна/решётки) отображаются как сплошные блоки.
- Нет вертикального прицеливания: снаряды остаются в горизонтальной плоскости, как в 2D.
- Наложения газа, огня и взрывов рисуются только на полу (они берутся из 2D-снимка пола).
- Небо процедурное, а не параллакс карты.
- Смещение глаза для оружия с прицелом и растворение спрайтов у курсора в 3D отключены.
- Постшейдеры спрайтов (2D-контур взаимодействия) нельзя нарисовать через `DrawEntity`; вместо этого
  подсвеченная сущность осветляется.
- У спрайтов, у которых есть слой с собственным шейдером, светящиеся слои всё равно освещаются (проход свечения не может их охватить).
- Обычная клавиша скриншота захватывает 3D-изображение (берёт итоговый кадр); вариант скриншота «без интерфейса» считывает скрытый 2D-вьюпорт.
- Облачка речи не скрываются, когда говорящий за стеной; значки статуса, полосы здоровья и подписи map-text скрываются.
- Перетаскивание с захваченной мышью начинается после примерно дюжины пикселей движения мыши.
- Режим GLES2 и нестандартное масштабирование DPI не тестировались.

## Как это работает

Обычный 2D-рендерер запускается во внеэкранный вьюпорт вокруг камеры. Мировой оверлей, расположенный чуть выше
`DrawDepth.HighFloorObjects`, копирует освещённый слой пола (тайлы, декали, лужи, трубы...) в текстуру. Затем фрагментный
шейдер выполняет рэймарчинг (raymarch) карты тайлов (стены) на GPU и накладывает текстуры на полы, потолки и космос. Каждая видимая сущность
отрисовывается через `DrawEntity` в покадровый атлас (плюс второй атлас только с её неосвещаемыми слоями) и выводится как
3D-квад с проверкой глубины (биллборды, плоские предметы, створки дверей, окна, столы, декали на стенах). Ввод идёт через
`IViewportControl`, поэтому все существующие 2D-системы, преобразующие экранную позицию в мировую, продолжают работать
с прицелом.

## Средства для разработчиков

`render3d.dev_channel=true` заставляет клиент опрашивать файл `render3d_dev_<player name>.txt` в своей пользовательской папке данных и выполнять каждую
строку как консольную команду (запускайте клиент с `--cvar player.name=<name>`, чтобы имя файла было предсказуемым).

| Команда | Назначение |
|---------|------------|
| `r3d_shot <name>` | PNG 3D-вида в `Screenshots/` |
| `r3d_look <yaw> <pitch>` / `r3d_look off`, `r3d_aim <x> <y>` | направить камеру (в градусах) или на точку пола |
| `r3d_cam fp\|tp` | режим камеры |
| `r3d_press <KeyFunction> [down\|up\|tap]` | синтетический ввод через настоящий путь вьюпорта (для предметов ближнего боя используйте `down`, паузу, `up`) |
| `r3d_capture on\|off` | принудительно включить путь захваченной мыши без фокуса окна |
| `render3d_tune` | открыть окно настройки: ползунок, поле или переключатель для каждой клиентской настройки `render3d.*`, применяется сразу; «Copy changes» копирует изменённые значения |
| `r3d_atlas <name>` | сохранить атлас спрайтов и его слой свечения как `atlas_<name>.png` / `atlasglow_<name>.png` |
| `r3d_audit <name>` | нарисовать каждую сущность следующего кадра отдельно в просторной ячейке, сохранить листы как `audit_<name>_<n>.png` и записать в лог ячейку атласа для каждой (рисунок за пределами ячейки в настоящем атласе ложится на соседа) |
| `r3d_pick`, `r3d_dump` | что находится под прицелом; все отрисованные сущности с их net id |
| `r3d_noself on\|off`, `r3d_glow on\|off` | исключить собственное тело из выбора; сравнить с атласом свечения и без него |
| `render3d_fx <effect> on\|off`, `render3d_quality ...` | переключение эффектов (также настоящие команды игрока), использовались для A/B-скриншотов в `docs/ss12/screenshots/visual_*` |

`render3d.debug_view` выбирает визуализации (1 снимок пола, 2 свет, 3 FOV, 4 лучи, 5 необработанный снимок пола, 6 глубина, 7 флаги
тайлов, 8 свет в точке попадания, 9 карта тайлов, 10 сетка 0). При включённом dev-канале клиент каждые
3 секунды пишет в лог строку `render3d: stats` (FPS и миллисекунды CPU по стадиям). В `Tools/render3d-dev/` лежат shell-помощники; `soak.sh <seconds>` запускает
прогон со случайным движением/обзором/щелчками и замеряет память.

## Конвейер импостеров (необязательно, этап 8)

`Tools/render3d-pipeline/` превращает спрайты статичных предметов в заранее отрендеренные 8-направленные RSI-импостеры
через TRELLIS.2 и headless Blender. Для настоящего запуска нужна CUDA-видеокарта от 24 ГБ; в этом репозитории поставляется только
путь пробного запуска без GPU (заглушки). См. его README.
